v0.3.0  (from v0.2.5)
--------------------------------------------------------------------------------

新功能
- Device Pack 線上更新（HT32: Online Update (Device Packs)）：
  從 GitHub holtek/HT32_STD_xxx_FWLib Releases 取得最新 .pack 下載連結，
  本機已有相同或更新版本時略過，下載後自動解壓至 extension 目錄；
  並發防護：_extracting guard 防止多次同時解壓
- Device Pack 手動安裝（HT32: Install from Pack Files）：
  從本機選取 Holtek.*.pack 檔案安裝，不限版本
- Welcome 畫面更新：移除「# Welcome to Holtek HT32 VS Code Extension」標題；
  「Update Extension」區塊改名為「Updates」，加入 Device Pack 更新入口

修正
- activationEvents glob 修正：`*/project.meta.json` → `.vscode/*/project.meta.json`
  修正：原 glob 只匹配一層，需要兩層（.vscode/<bgDir>/project.meta.json）才能正確觸發 activation
- 開啟專案時新增 validateProjectFiles 前置驗證：
  逐一檢查每個 bgDir 的 project.meta.json 及 project.settings.json 是否存在且為合法 JSON
  全部無效 → modal 錯誤對話框 → 自動關閉 workspace → 聚焦回 HT32 panel；
  部分無效 → warning toast（打開 Output Channel 顯示詳情）→ 跳過壞的繼續開啟有效的；
  全部無效時自動從 HT32 recent projects 移除對應 .ht32vs（removeRecentProject）
- 修正 catch fall-through：initProjectsFromMeta 失敗時 catch block 加入 return false，
  不再落穿到 tree.setRoot(root) 與 setContext hasProject=true
- 修正 setActiveBuildGenSetting / addRecentProject 意外遺失：
  開啟專案每次清除 activeBuildGen、成功後更新 recent projects 記錄

v0.2.4  (from v0.2.3)
--------------------------------------------------------------------------------

新功能
- 新增 `HT32: Regenerate Makefile` 命令（Command Palette）：
  從 project.meta.json + project.settings.json 重新產生 Makefile，
  無需重新 Convert；用於 Makefile 損壞或格式過舊的復原。
  多專案時顯示 QuickPick 選擇目標；Makefile 遺失的 Project 也可正常選取。

修正
- HT32-IDE 轉換：改為永遠優先讀取 .project（使用者當前專案檔），
  只在 .project 不存在時才 fallback 到 original.project（舊備份）；
  修正因 original.project 為舊版備份導致後來新增的 ht32_op2.c 在轉換後消失的問題
- updateProjectMeta 在 Makefile 缺少 `# ---- Dirs ----` sentinel 時
  從靜默無效改為顯示警告，提示使用者執行 `HT32: Regenerate Makefile`
- generateTasksAndLaunch 工具鏈安裝完成後的遞迴呼叫改以 isRetry flag 限制深度，
  避免工具鏈安裝失敗時無限遞迴
- resolveToolchain 加入 _toolchainInstallPromise 防護，多個並發呼叫時
  只顯示一次「toolchain not found」通知，避免重複彈窗
- toolchain.ts：clangd.arguments 讀取改用 Array.isArray 防禦，
  避免 settings.json 中該值為非陣列型別時 spread 報錯

v0.2.3  (from v0.2.0)
--------------------------------------------------------------------------------

新功能
- Afterbuild .bat 自動同步：Convert uVision / HT32-IDE 後，若專案 Post-build Command 指向
  afterbuild.bat / afterbuild_ap.bat / afterbuild_iap.bat / dfumaker_combo.bat /
  srec_make_combo.bat，自動比對 extension 內建版本的 $Rev 號；
  若內建版本較新（且 $Rev 未超過允許上限），自動替換並將原檔備份為 .bak
  允許上限（MAX_REPLACEABLE_REV）：afterbuild 435 / afterbuild_ap 437 /
  afterbuild_iap 358 / dfumaker_combo 359 / srec_make_combo 527
- Stack Analysis：misc.c weak symbol 衝突自動修補（patchMiscCWeak）
  偵測到 misc.c 含舊版 USART_Configuration / HT32_DVB_USBConnect 強符號時，
  自動加 __attribute__((weak))，讓 ht32_stack_analysis.c 的版本可覆蓋
- clangd `--query-driver` pattern 從單一 gcc 可執行路徑改為 `arm-none-eabi-*`，
  涵蓋同目錄所有工具（objcopy、objdump 等），修正部分環境 IntelliSense 無法啟動的問題
- clangd `-isystem` 路徑改由 gccPath 直接推算（不再從 clangd.arguments 反推），
  確保 convert / create project 都能正確產生 include 路徑

修正
- CFLAGS / ASFLAGS 加入 `-ffile-prefix-map=$(CURDIR)=.`：
  移除 debug info 中的絕對路徑前綴，讓相同 source 在不同機器 build 出一致的 debug info；
  `-T <linker_script>` 及 `-ffile-prefix-map` 加引號，修正路徑含空格時 build / regenerate 失敗
- Convert 後自動切換到 Problems panel（含 prebuilt binary 跳過警告）：
  prebuilt 與 convert warnings 的 pending file 統一只在需要 reload 時寫入，
  避免 pending file 殘留被下次開啟時誤顯示
- Debug config cwd 修正為各 Project 目錄（bgCwdOf）而非固定 workspaceFolder，
  多專案下各 Project 的 GDB server 工作目錄正確
- OpenOCD `ht_flash write_image` 路徑改用 TCL `{...}` 括起，修正路徑含空格時燒錄失敗
- Excluded from build 檔案不再顯示為 Problems panel 警告（改為 Output Channel log only）
- include path regex 修正：includes.list 同時支援 `-I"path"` 與 `-Ipath` 兩種格式

v0.1.8  (from v0.1.7)
--------------------------------------------------------------------------------

[Per-file Settings]
- 新增 ht32.treeFileSettings 指令：右鍵 TreeView 檔案節點 → File Settings...
  以迴圈式 QuickPick 呈現目前設定狀態（checkmark 顯示已啟用項目），選 Apply 存檔並重產 Makefile
- 支援三項 per-file 設定：
  Exclude from build：檔案保留在 groups（TreeView 可見），不加入 sources.list / Makefile SRCS
  Execute-only：對該 .c 加 -mpure-code 編譯旗標（防止逆向，需 MPU 配合）
  ROM Region：從 linker script 解析可用 ROM region 供選擇；自動在 .text section 前插入
               `.ht32rom_<name> : { *<file>.o(.text* .rodata*) } > <region>`
               目標 region 已存在（如 SPIM）時直接重用，不重複新增 MEMORY 行
- Convert uVision：自動讀取 Keil per-file XML（FileOption 節點）
  IncludeInBuild=0 → exclude；useXO=1 → xo；RVCTCodeConst=5 → rom（IROM2/SPIM 位址）
  OCR_RVCT 位址表由 extractOcrRvctMap() 從 uvprojx 第一個 Target 解析
- patchLinkerScriptRom()：負責 linker script 的加/移除
  Step 1：移除所有舊有 HT32ROM_ MEMORY 行與 .ht32rom_ SECTIONS block
  Step 2：解析現有 MEMORY regions（origin → name Map），避免新增重疊 region
  Step 3：對新 region 以 hex 格式寫入 MEMORY（ORIGIN=0x...，LENGTH=0x...），插在 RAM 之前
  Step 4：在 .text section 前插入 output section，region 名稱優先使用已存在的（如 SPIM）
- TreeView 視覺標示：
  excluded 檔：ThemeIcon('circle-slash', disabledForeground) + description 加 [excluded]
  xo / rom 檔：description 加 [xo] / [rom] tag（保留原 file type icon）
- ldRomRegions() helper：解析 linker script MEMORY 區塊，回傳所有無 'w' flag 的 region
  供 ROM Region QuickPick 選單動態填入（FLASH、SPIM 等），並標示目前已選項目

[FWLib Bundled Templates Fallback]
- 三條轉換路徑（Convert uVision / Convert HT32-IDE / Create Project）在找到 FWLib root
  但 project_template/ 不存在時，自動 fallback 到 extension 內建 bundled templates
  位置：templates/{familyTag}/GNU_ARM/（startup .s、ht32_op.c、linker.ld）
  修正：FWLib 若只有 library/ 子結構而無 project_template/（如單獨取出的 driver 包），
  原本直接報錯「Cannot locate FWLib template directory」，現可正常完成轉換
- familyTag 正規式從 [FL] 改為 [A-Za-z]+，支援未來可能出現的新系列前綴字母
- resolveGnuArmDir()：找到 FWLib root 後若 project_template/ 不存在，
  呼叫 bundledGnuDirFromFwlRoot() 取得對應 bundled 路徑

[Create Project — FWLib 系列判斷改與 Convert 一致]

  原本檢查 project_template/IP/Example/GNU_ARM/ 是否存在；改為與 Convert uVision 相同的

  原本所有 define 都放進 defines.list，C compiler 與 assembler 共用同一份；

[scatter2ld — name.o(+XO/+RO) 物件固定位址映射]

  支援 +XO / +RO / +RW / +ZI，`+FIRST` modifier 亦支援

  +RW → `.data .data*`；+ZI → `.bss .bss*`

  覆蓋 pyocd.yaml 的 `connect_mode: under-reset`，pyocd 連線時不碰 reset line
  MCU 繼續執行，GDB attach 後 `monitor halt` 停在 current PC
- OpenOCD Attach：移除所有 HLM target cfg 的 `connect_assert_srst`
  受影響檔案：openocd/scripts/target/ 下的
    HLMm0x.cfg / HLMm3x.cfg / HLMm4x.cfg / HLM490x1.cfg / HLM491x3.cfg / HLM493x5.cfg
  根因：`connect_assert_srst` 告訴 OpenOCD init 時 assert SRST（硬體 reset）；
  這個動作在 openOCDLaunchCommands 的 reset_config override 之前發生，
  導致 attach 時 MCU 被 reset 而非停在 current PC
  修正後：OpenOCD init 不 assert SRST；Debug 模式 reset 由 postLaunchCommands
  的 `monitor reset halt` 明確發出
